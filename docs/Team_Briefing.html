AI Through Maths, and What We Are Doing With It

Briefing for a new team member · Alameda County traffic-safety research project · 15 Nov 2026

1. What "AI" actually is: a function fitted to data

Almost everything called AI in this project is one idea. There is a function f that takes inputs x and returns a prediction ŷ = f(x; θ). The numbers θ are the parameters. "Learning" means choosing θ so the predictions match data we already have. There is no magic step; it is optimisation.

The recipe. Data: pairs (xi, yi), i = 1…n. A loss measures how wrong one prediction is, ℓ(y, ŷ). Total loss L(θ) = Σi ℓ(yi, f(xi; θ)). Learning is
θ̂ = argminθ L(θ)

The simplest case: linear regression

Take f(x; β) = β0 + β1x1 + … + βpxp and squared loss ℓ = (y − ŷ)². Stack the inputs into a matrix X (one row per example). Setting the derivative of L to zero gives the normal equations and the answer in closed form:

β̂ = (X⊤X)−1 X⊤y

Geometrically, Xβ̂ is the orthogonal projection of y onto the column space of X. If you have done linear algebra, you already know how the most basic "AI model" works.

When there is no closed form: gradient descent

For most models the minimum cannot be written down. Instead we walk downhill. The gradient ∇L points in the direction of steepest increase, so repeat

θ ← θ − η ∇L(θ)
with a small step size (learning rate) η. Neural networks, including the large language models behind chatbots, are trained this way, just with millions or billions of parameters.

Vocabulary

  • Features x: the inputs we choose. Target y: what we predict. Parameters θ: learned. Hyperparameters: set by us, not learned (for example the penalty λ on page 3).
  • Training data is what θ is fitted on; test data is data the model never saw, used to judge it honestly.
In our project. One row is one quarter-mile street segment (there are 32,462 in Alameda County). The features are road class, traffic volume, lanes, intersections, schools and bus stops nearby, population density and more. The target is the number of killed-or-seriously-injured (KSI) crashes. The goal is to predict which streets will have serious crashes before they happen, and to say where limited money prevents the most.

2. Probability: why crash counts need a different loss

Squared loss quietly assumes errors are symmetric with the same spread everywhere. Crash counts are not like that: they are non-negative integers and mostly zero (a typical segment has no serious crash in a year). So we model the distribution of the data, not just its centre.

The Poisson distribution

If crashes arrive independently at a steady average rate, the count Y over a period follows a Poisson distribution with mean μ:

P(Y = k) = e−μ μk / k!,   E[Y] = Var(Y) = μ

Maximum likelihood: the general form of "choose θ to fit"

The likelihood is the probability the model gives to the data we saw. We choose θ to maximise it, which is the same as minimising the negative log-likelihood, so the loss is −log P(data | θ). For Poisson counts:

log 𝓛(θ) = Σi [ yi log μi − μi − log(yi!) ]

Squared loss is the special case where the errors are assumed Gaussian. Choosing a loss is choosing a probability model.

Poisson regression with an exposure offset (our main model)

log μi = β0 + β1x1i + … + βpxpi + log ti

Here ti is exposure: segment length in miles times years observed. Because log ti enters with coefficient 1 (an "offset"), the expected count is μi = ti × rate, so a segment twice as long has twice as many expected crashes. The log link also makes effects multiplicative: raising xj by one unit multiplies the rate by eβj, called the incidence rate ratio (IRR). IRR 1.19 means 19% more crashes.

Overdispersion

Real counts vary more than Poisson allows (Var > mean) because segments differ in ways we do not measure. The negative binomial fixes this with an extra parameter α:

Var(Y) = μ + αμ2

Page 4 uses α directly.

Standard errors and intervals

The maximum-likelihood estimate β̂ is approximately normal with a standard error SE, so a 95% interval is β̂ ± 1.96 SE, and for the IRR we exponentiate both ends. The formula assumes independent observations. Neighbouring segments of one street are not independent, so we cluster the standard errors by street; ignoring this makes intervals too narrow.

Worked example from our data. Across 120 intersections with counts, we fitted log μ = c + β log(pedestrians + 1) and got β̂ = 0.41 (95% interval 0.24 to 0.57). Doubling the pedestrians multiplies expected pedestrian crashes by 20.41 ≈ 1.33, not by 2. This is a log-log slope (an elasticity): slope 1 would mean crashes proportional to people; below 1 is the "safety in numbers" pattern.

3. Fitting versus memorising: overfitting and honest testing

A flexible enough function can reproduce the training data perfectly and still predict nothing. For squared error, the expected test error splits into three parts:

E[(y − ŷ)2] = Bias2 + Variance + Noise

More flexibility lowers bias but raises variance. Training error only ever falls as the model gets more flexible; test error is U-shaped. So the only fair question is how a model does on data it has not seen.

Three defences we use

  • Forward-in-time holdout. Fit on crashes from 2016 to 2022, score on 2023 to 2025. This matches real use: predict the future from the past.
  • Spatial holdout. Hold out whole 5 km grid cells so the model cannot lean on neighbouring segments that share unmeasured traits.
  • Regularisation. Penalise large coefficients. Ridge regression minimises L(β) + λ Σj βj2. The penalty λ is a hyperparameter chosen by cross-validation. We predict pedestrian counts from land-use features with ridge and score it by leave-one-out R2 = 1 − Σ(y − ŷ)2 / Σ(y − ȳ)2, which on held-out sites was 0.44.

Gradient boosting

Build the prediction as a sum of many small decision trees, f(x) = Σm=1M η hm(x). Each new tree hm is fitted to the negative gradient of the loss at the current prediction, so the procedure is gradient descent in "function space". We boost with the Poisson loss above. In our data it performed about the same as the plain Poisson regression, so the simpler model wins ties.

Neural networks and language models (the AI in the news)

A neural network composes simple functions: f(x) = WL σ(… σ(W2 σ(W1x))), where the W are matrices and σ is a nonlinearity such as max(0, z). Gradients come from the chain rule applied layer by layer (backpropagation). A language model reads text as tokens and outputs a probability for the next token with the softmax:

P(token j) = ezj / Σk ezk

and it is trained to minimise the cross-entropy −Σ log P(true next token), which is the same negative-log-likelihood idea as the Poisson loss. Its core operation, attention, is softmax(QK⊤/√d)V: a weighted average of vectors with weights from dot products.

Why this matters for how we work. A language model is trained to produce plausible text, not verified text. The code and drafts that Claude produced for this project are useful and fast, and they can still be confidently wrong. So every number in our write-up must trace to a committed result file, and every method must be checkable by a human who understands the maths. That is part of your job.

4. Bayes, shrinkage, and regression to the mean

Bayes' rule combines prior knowledge with evidence: P(θ | data) ∝ P(data | θ) P(θ). The posterior balances the two, in proportion to how informative each is.

The problem: lucky and unlucky places

A segment had 3 serious crashes in 3 years while similar segments had 0.4. Is it dangerous, or unlucky? Serious crashes are rare random events, so the places with the highest counts are partly the unluckiest ones. Next period they tend to come back down with no intervention at all. This is regression to the mean. It causes two errors: ranking streets by raw counts over-picks unlucky ones, and a fix installed at a high-count place looks like it worked even when it did nothing.

Empirical Bayes (EB): use both the model and the history

Let μ be what the model predicts for this segment (what similar streets typically get) and y its own observed count over the same period. If true rates vary across segments like a gamma distribution, Poisson counts give a negative binomial, and the posterior mean is a weighted average:

EB = w μ + (1 − w) y,   w = 1 / (1 + αμ)

(standard form, with μ as the expected count over the period and α the overdispersion from page 2). When the segments differ only a little (small α), w is near 1 and we trust the model. When they differ a lot, we trust the segment's own record.

Illustrative numbers (not from our data). μ = 1.0 expected crashes, α = 0.5, so w = 1/(1 + 0.5) = 0.667. The segment actually had y = 4. EB = 0.667 × 1.0 + 0.333 × 4 = 2.0. The estimate is pulled from 4 toward the model's 1.0: that pull is called shrinkage. It removes most of the luck.

What it bought us

  • EB beat ranking by raw crash history at the top of the list by 5 to 8 percentage points of later serious crashes captured, on held-out 2023 to 2025 data.
  • EB is the ranking used for budget allocation (page 7). Its advantage over raw history there is clear for large budgets but not for small ones; the intervals tell us that, as page 5 explains.

Testing many places at once

If you test thousands of places for "hot spots" at the 5% level, about 5% will look hot by chance alone. The Benjamini–Hochberg procedure controls the false discovery rate: sort the m p-values p(1) ≤ … ≤ p(m) and flag every place up to the largest k with p(k) ≤ (k/m) q. We use it with the Getis–Ord G* statistic, which compares the crash count in a neighbourhood to what random placement would give.

Why this matters here. Our whole question is where to spend money. If rankings mostly reflect luck, the money goes to places that would have improved anyway. Everything we do about evaluation, including holding out future years, exists to keep luck from being mistaken for risk.

5. Uncertainty, cause and effect, and optimisation

The bootstrap: how much would our answer change with different luck?

We have one dataset but want to know how much a statistic T (a ratio, a slope, a difference between strategies) would vary. Treat the data as a stand-in for the population:

  1. Resample the units with replacement, giving a new dataset of the same size.
  2. Recompute T on it, giving T*1. Repeat B times (we use 1,000 to 2,000).
  3. The 2.5th and 97.5th percentiles of T*1, …, T*B form a 95% interval.

We resample whole streets, not single segments, because segments on one street move together. To compare two strategies we rescore both on the same resample and look at the ratio, so the luck common to both cancels (a paired comparison). If a ratio's interval includes 1, we cannot tell the strategies apart.

Cause and effect: difference-in-differences

Did a countermeasure reduce crashes? Compare how crashes changed on treated streets with how they changed on similar untreated streets. In our version the effect is a ratio of ratios:

effect = ( Tafter / Tbefore ) / ( Cafter / Cbefore )

A value below 1 means treated streets improved relative to controls. It is valid only if the two groups would have moved in parallel without the treatment. Because projects are built where crashes were high (regression to the mean again), we match treated and control streets on prior crashes and road class. Even then it is observational. A correlation is not a cause: the pedestrian slope of 0.41 does not show that adding walkers makes a street safer.

Optimisation: spending a fixed budget

Let option (i, j) be treatment j at segment i, with cost cij and benefit bij = CRFj × expected serious crashes at segment i (the crash reduction factor CRF is a published percentage, 35% for the fixes we use). Choose xij ∈ {0, 1} to

maximise Σi,j bij xij   subject to   Σi,j cij xij ≤ B,   Σj xij ≤ 1 for every i

This is a multiple-choice knapsack, an integer linear program. It is hard in general, but a solver (HiGHS) finds the exact optimum for our ~12,000 options. We then score each strategy on crashes that happened after it chose, so we compare "what we would have bought" with "what actually happened", not with what the model predicted.

(2) Show that maximising the Poisson log-likelihood with log link gives the score equation Σ(yi − μi)xi = 0. (3) Show EB = wμ + (1 − w)y follows from a gamma prior on the rate with mean μ and variance αμ2. (4) Why is the bootstrap percentile interval for a ratio not symmetric around the estimate?

6. What we are doing: three levels

High level: the question and why it is worth a paper

Where do serious crashes (people killed or seriously injured) concentrate in Alameda County, who bears them, and which affordable fixes would prevent the most? The output is a research paper plus a public, reproducible code repository, and an OSF registration so our methods are time-stamped. It is original because Alameda CTC's 2024 High-Injury Network (HIN) and Proactive Safety Network (PSN) were never tested against later crashes, nothing weighs destinations by exposure, and no one scores budget allocations on what actually happened afterward. We test all three out of sample on 2023 to 2025 crashes.

Medium level: five parts, each a question with a method

PartQuestionMethod (maths from sections 2 to 5)
1 BaselineWhat happened 2016 to 2025, when, to whom?Counts and rates; Getis–Ord hot spots with Benjamini–Hochberg.
2 Hot spots and destinationsDo HIN/PSN find later serious crashes? Are children hurt near schools on school days? Is exposure (people walking) driving crash counts?Share of later KSI per road length vs baselines; Poisson IRRs with street-clustered errors; school-year vs summer with placebo hours; log-log slope on counts.
3 CountermeasuresDid bike lanes (and later signs, signals) change crashes?Matched difference-in-differences, cell bootstrap.
4 PredictionWhich segments will have serious crashes?Poisson regression and boosting with exposure offset; Empirical Bayes; forward-in-time and spatial holdout.
5 AllocationGiven a budget, what should we fix where?Multiple-choice knapsack; scored on 2023 to 2025; bootstrap intervals.

Low level: how it is built and what you will touch

  • Data flow. 73,565 injury and fatal crashes (CHP SWITRS via UC Berkeley TIMS, linked to CCRS) → geocoded points → snapped to 32,462 quarter-mile segments → a segment × year panel → joined with traffic volume (HPMS), OpenStreetMap, Census, schools, hospitals, transit, bike/pedestrian counts.
  • Code. One script per analysis, run as python -m analysis.<name> (for example school_test, model, allocate_bootstrap). Each script's header states its design before the results; each writes a table to analysis/results/ and is explained in a file in docs/.
  • Definitions. KSI = TIMS severity 1 or 2. Surface streets only (freeways excluded). HIN is a network of the streets with the most pedestrian and bicycle serious crashes; PSN scores streets by traits and nearby destinations with no crash data.
  • Hard rules. The repo is public: no restricted data (the Alameda CTC travel-model volumes we may receive, and the HIN/PSN lines) is ever committed. Treatment costs in the allocation are assumptions, so dollar figures are not findings. Every number in writing must come from a committed result file.
